# BrotherHub для разработчиков

## Как это работает

- У каждого участника видео открывается у себя: по ссылке (через yt-dlp) или
  из локального файла. По сети передаются только команды и позиция, поэтому
  требования к интернету минимальные.
- Ведущий — источник времени: его пауза, запуск и перемотка уходят на сервер,
  плюс раз в 2 секунды он сообщает позицию. Остальные подстраиваются: при
  небольшом расхождении — скоростью ±5 %, при большом — перемоткой.
- Сервер хранит комнаты в памяти, пересылает чат и состояние воспроизведения.
  При обрыве связи 30 секунд держит место за участником.
- Голос идёт через LiveKit; пропуск в голосовой канал (JWT на 5 минут, только
  микрофон) выдаёт наш сервер после проверки пароля.

## Структура

| Папка            | Что внутри                                                        |
|------------------|-------------------------------------------------------------------|
| `shared/`        | Протокол: типы сообщений клиент ⇄ сервер                          |
| `server/`        | Сервер (axum + WebSocket): комнаты, чат, синхронизация, пропуска в голос |
| `app/`           | Приложение на Tauri 2, интерфейс на React + TypeScript            |
| `app/src-tauri/` | Rust-часть приложения: связь с сервером, mpv, встраивание видео, синхронизация, «нажми и говори» |
| `deploy/`        | Запуск на сервере: Docker Compose, LiveKit, Caddy                 |
| `scripts/`       | Сборка: архив плеера mpv, сборка релиза                           |
| `docs/`          | Инструкции                                                        |

## Стек

- Rust; интерфейс — React + TypeScript, шрифты Manrope и Unbounded
- Tauri 2 (Windows)
- mpv + yt-dlp, управление через JSON IPC; видео встроено в окно (`--wid`)
- LiveKit (WebRTC) для голоса

## Логи

`app/src-tauri/src/logs.rs`. Всё лежит в `%LOCALAPPDATA%\com.ferrumnyak.brotherwatch\logs\`:
папка `1` — последний запуск, `2`…`5` — предыдущие (старше удаляются). Внутри —
`brotherwatch.log` (подключение, ссылки, ошибки, скачивание плеера) и
`mpv-<n>.log` (журнал mpv по `--log-file`, вместе с выводом yt-dlp). Пароли и
токены в журнал не пишутся. В интерфейсе — кнопка «Открыть папку с логами».

В `npm run tauri dev` записи приложения дублируются в консоль.

## Сертификаты для mpv

libcurl внутри mpv проверяет HTTPS по своему списку, а не по хранилищу Windows,
поэтому сайты с корнями, которые есть только в Windows (например, «Russian
Trusted Root CA» у части серверов VK), в mpv не открывались. `certs.rs` при
запуске собирает `ca-bundle.pem` в папке приложения: корни Mozilla
(`app/src-tauri/certs/mozilla-roots.pem`) + корни из Windows — и передаёт его
mpv через `--tls-ca-file`. Список Mozilla стоит изредка обновлять.

## Ускорение YouTube (ByeDPI)

`dpi.rs` (только компьютер) скачивает в папку данных `byedpi\ciadpi.exe`
(ByeDPI, версия и SHA-256 архива закреплены в коде) и запускает его как
локальный прокси `127.0.0.1:<свободный порт>` с `--http-connect`. Драйверов и
прав администратора не нужно: через прокси ходит только само приложение —
mpv (`--http-proxy` и `proxy=` для его yt-dlp), остальные вызовы yt-dlp
(`--proxy`) и окно «Обзора» (`proxy_url`). ByeDPI запутывает только домены
YouTube (`--hosts`), остальное после `--auto=none` проходит без изменений.

Кнопка «Найти лучший обход» (`dpi_find_best`) берёт через yt-dlp прямую
ссылку на поток тестового ролика, замеряет скорость без обхода и с каждым
набором из `PROFILES` (по 6 секунд) и включает самый быстрый, если он
заметно быстрее, чем без обхода. Выбор хранится в `dpi.json` в папке
данных. Сами проверки не повторяются — только по кнопке. Упавший ciadpi
перезапускается; «Обзор» с устаревшим прокси пересоздаётся при открытии.
